You have an Azure Linux virtual machine that has the Custom Script Extension installed. The extension is showing a failed status, and you need to troubleshoot the issue by reviewing the extension logs. Where should you look for the extension logs on the virtual machine?

On an Azure Linux VM, the Custom Script Extension logs are stored under the Azure agent’s extension directory and log files.

You should check:

Extension-specific logs:

/var/log/azure/custom-script-extension/
(commonly includes handler.log, which shows execution details and failures)

Azure Linux agent logs (for broader troubleshooting):

/var/log/waagent.log
In most troubleshooting scenarios, the primary file to inspect is handler.log inside /var/log/azure/custom-script-extension/, as it contains the script execution output and error details.

So the key location to start with is:
👉 /var/log/azure/custom-script-extension/handler.log

To change the Usage location for all users in the Accounting department using Microsoft Graph PowerShell, you need to:

Find the users in the Accounting department

You are creating a custom Azure Policy definition that automatically adds a tag to resources when the tag is missing. You need to configure the policy to add the tag during resource creation and allow remediation of existing non-compliant resources. Which effect should you use in the policy definition?

Use the modify effect.

Why modify?
You need a policy that:

Automatically adds a tag during resource creation

Supports remediation for existing non-compliant resources

The modify effect is specifically designed for this scenario because it:

Can add, update, or remove resource properties (like tags)

Works at deployment time

Supports remediation tasks via a remediation deployment

Why not the others?
append → only adds values, but does not support remediation of existing resources

deployIfNotExists → used to deploy related resources, not modify existing properties like tags

audit / deny → only evaluate compliance, no changes made

Final Answer:
👉 Use the modify effect

You have an Azure subscription that contains multiple resource groups. A user named User1 has the following role assignments: Contributor role at the subscription scope and Reader role on a resource group named RG1. What are the effective permissions for User1 on resources in RG1? 
Contributor permissions
Explanation
Azure RBAC is an additive model, so the effective permissions are the sum of all role assignments. When a user is granted the Contributor role at the subscription scope and the Reader role on a resource group, the sum of the Contributor permissions and Reader permissions is effectively the Contributor role for that resource group. The Reader role assignment has no additional impact since Contributor already includes all Reader permissions. Reference: https://learn.microsoft.com/en-us/azure/role-based-access-control/overview
