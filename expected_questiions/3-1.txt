You have an Azure Policy assignment that uses a policy definition with the modify effect to automatically add a required tag to storage accounts. The policy evaluates existing storage accounts and marks several as non-compliant. What must you configure to update the existing non-compliant storage accounts with the required tag?

You must configure a remediation task for the Azure Policy assignment.

The modify effect can automatically fix resources during create/update operations, but existing resources that are already marked non-compliant require remediation to apply the changes retroactively.

So the flow is:

Policy with modify effect identifies non-compliant storage accounts.

Create a remediation task on the policy assignment.

Azure uses the managed identity associated with the policy assignment to add the required tag to existing storage accounts.

Key requirement:

The policy assignment must have a managed identity with the necessary permissions (typically Tag Contributor or similar).

Host header 가 뭐야?

Host header는 HTTP 요청에서 “어느 도메인으로 접속했는지”를 알려주는 값이야.

📌 기본 개념
브라우저가 서버로 요청을 보낼 때 이런 정보를 같이 보냄:

GET / HTTP/1.1
Host: www.example.com
여기서:

Host: www.example.com ← 이게 Host header

서버는 이 값을 보고 “어떤 사이트 요청인지” 판단함

📌 왜 필요하냐?
하나의 서버(IP)에 여러 웹사이트가 있을 수 있기 때문이야.

예:

example.com

blog.com

shop.com

이게 모두 같은 서버로 가도:

Host: blog.com   → 블로그 사이트 보여줌
Host: shop.com   → 쇼핑몰 보여줌
즉, Host header가 “사이트 구분자” 역할을 함.

📌 Azure App Service에서 중요한 이유
App Service는 내부적으로:

webapp1.azurewebsites.net
이 Host 기준으로 요청을 처리해.

근데 사용자가:

www.mycustomdomain.com
으로 접속하면 Host header는:

Host: www.mycustomdomain.com
이렇게 됨.

👉 App Service 입장에서는 “내 도메인 아닌데?” 하고 문제 생길 수 있음.

📌 Application Gateway가 하는 역할
Application Gateway는 중간에서 Host header를 바꿀 수 있음:

사용자 요청:

Host header는 “이 요청이 어떤 도메인으로 들어왔는지”를 알려주는 HTTP 필드이고, 서버가 올바른 사이트/앱을 선택하는 기준이다.

Enable 'Pick host name from backend target' in the backend HTTP settings.
Explanation
When App Service is used as a backend, enabling 'Pick host name from backend target' dynamically sets the host header in the request to the host name of the backend pool. This is required because an app service is a multitenant service that uses a shared space with a single IP address and can only be accessed through the hostnames configured in its settings. Automation Runbook은 Azure 리소스를 관리하는 자동화 도구이고, Custom Script Extension은 VM 내부에서 스크립트를 실행하는 기능이다.


Azure 관리 레벨 -> 이게 뭐지?

좋은 질문이야. 여기서 “Azure 관리 레벨(management plane)”이라는 건:

Azure 리소스를 ‘관리’하는 API 영역

을 말해.

Azure는 크게 2개로 나눠 생각하면 쉬워:

1️⃣ Management Plane (관리 레벨)
👉 Azure 리소스를 관리하는 영역

예:

VM 생성/삭제

VM 시작/중지

Storage 생성

권한 설정

NSG 변경

즉:

"Azure 리소스를 컨트롤"
하는 영역.

📌 예시
Runbook에서:

Stop-AzVM
이건:

VM 안에 들어가는 게 아님

Azure API에:

“VM 꺼라”

라고 명령 보내는 것

2️⃣ Data Plane (실제 내부 작업)
👉 리소스 내부 데이터/OS 접근 영역

예:

VM 내부 파일 수정

DB 데이터 읽기

Blob 내용 읽기

IIS 설치

즉:

"리소스 내부 작업"
📌 Custom Script Extension은?
이건 VM 내부에서 실행됨:

Install-WindowsFeature Web-Server
👉 실제 OS 안에서 실행됨.

📌 비유
Management Plane
건물 관리실에서 전원 ON/OFF

Data Plane
실제 방 안에 들어가 가구 배치

📌 Automation Runbook이 관리 레벨인 이유
Runbook은 보통:

Azure REST API

Az PowerShell

ARM

같은 걸 통해 Azure 리소스를 제어함.

즉:

Automation → Azure API → VM 관리
🔑 핵심 한 줄
Management plane은 Azure 리소스를 생성·수정·제어하는 영역이고, Data plane은 리소스 내부 데이터나 OS를 다루는 영역이다.


You have an Azure storage account that hosts file shares. You enable Microsoft Entra Domain Services authentication for the storage account. A security group named FileUsers needs read and write access to a file share named share1 over SMB. Which built-in role should you assign to the FileUsers group at the file share level?

정답은:

Storage File Data SMB Share Contributor

📌 문제 핵심
상황:

Azure File Share 사용

Microsoft Entra Domain Services 인증 활성화

SMB 통해 접근

FileUsers 그룹에:

읽기 ✔

쓰기 ✔
권한 필요

📌 Azure Files SMB용 RBAC 역할
1. Storage File Data SMB Share Reader
읽기만 가능

❌ 쓰기 불가

2. ✅ Storage File Data SMB Share Contributor
읽기 ✔

쓰기 ✔

파일 생성/수정 가능 ✔

👉 문제 요구사항과 정확히 일치

3. Storage File Data SMB Share Elevated Contributor
NTFS permission 변경 가능

너무 강한 권한

📌 중요한 포인트
Azure Files SMB 인증에서는:

Azure RBAC

NTFS ACL

둘 다 함께 사용 가능

근데 문제는:

“built-in role at file share level”

이라고 했으므로 RBAC 역할 묻는 문제야.

🔑 한 줄 정리
Azure Files에서 SMB를 통해 읽기/쓰기 권한을 주려면 Storage File Data SMB Share Contributor 역할을 할당한다.


Microsoft Entra Domain Services 가 뭐야? SMB 가 뭐야?

좋아. 이 문제는 용어가 어려워서 헷갈리는 거야. 하나씩 아주 쉽게 보면 돼.

1️⃣ SMB가 뭐냐?
SMB는:

파일 공유 프로토콜

이야.

Windows에서 흔히 쓰는:

\\server\share
이 방식이 SMB야.

📌 쉽게 말하면
회사 네트워크에서:

공유 폴더 접근

네트워크 드라이브 연결

할 때 쓰는 기술.

📌 Azure Files도 SMB 지원
Azure Storage 안의 File Share를:

\\storageaccount.file.core.windows.net\share1
처럼 네트워크 드라이브처럼 사용 가능.

2️⃣ Microsoft Entra Domain Services 가 뭐냐?
이건 쉽게 말하면:

Azure에서 제공하는 “관리형 Active Directory”

야.

📌 원래 회사 AD 환경
보통 회사엔:

Active Directory 서버

Domain Controller

LDAP/Kerberos

같은 게 있음.

📌 그런데 Azure에서는?
Microsoft가 대신 제공:

“AD 서버 직접 설치하지 말고 우리가 관리해줄게”

→ 이게 Microsoft Entra Domain Services (예전 Azure AD DS)

📌 그래서 가능한 것
Azure VM이나 Azure Files가:

도메인 로그인

Kerberos 인증

그룹 기반 접근 제어

같은 전통적인 Windows AD 기능 사용 가능.

📌 이 문제 전체 해석
문제를 쉬운 말로 바꾸면:

Azure 공유 폴더를
회사 AD 계정으로 로그인해서
읽기/쓰기하게 만들고 싶다

야.

📌 구조 그림
User (AD 계정)
   ↓ SMB 로그인
Azure File Share
   ↓
Entra Domain Services 인증
📌 그래서 왜 역할 필요?
FileUsers 그룹에게:

읽기

쓰기

권한을 줘야 해서:

👉 Storage File Data SMB Share Contributor

역할을 준 거야.

🔑 핵심 한 줄
SMB = Windows 파일 공유 방식

Entra Domain Services = Azure의 관리형 Active Directory

둘을 합쳐 Azure File Share를 “회사 파일 서버처럼” 사용하는 구조다.


SMB 뭐의 약자야?

SMB는:

Server Message Block

의 약자야.

📌 이름 의미
직역하면:

Server = 서버

Message = 메시지

Block = 블록(데이터 단위)

즉:

서버와 파일/프린터 데이터를 주고받는 프로토콜

📌 실제로 하는 일
SMB로 가능한 것:

네트워크 파일 공유

공유 폴더 접근

프린터 공유

네트워크 드라이브 연결

📌 Windows에서 많이 봤던 형태
\\fileserver\shared
이게 SMB 공유 경로야.

📌 Azure에서 SMB
Azure Files도 SMB 지원해서:

\\storageaccount.file.core.windows.net\share1
처럼 접근 가능.

🔑 한 줄 정리
SMB(Server Message Block)는 Windows 기반 네트워크 파일 공유 프로토콜이다.


security group 은 또 뭐야?

여기서의 security group은 NSG(Network Security Group)가 아니라:

사용자들을 묶는 AD/Entra 그룹

이야.

즉:

사람(User)

또는 컴퓨터

를 묶어서 권한을 주는 그룹.

📌 쉽게 말하면
예:

FileUsers 그룹
 ├── Jason
 ├── Alice
 └── Bob
그리고 이 그룹에:

share1 읽기/쓰기 권한
을 주는 거야.

📌 왜 그룹을 쓰냐?
개별 사용자마다 권한 주면 관리 어려움.

그래서:

사람 추가 → 그룹에 넣기

사람 제거 → 그룹에서 빼기

만 하면 권한 자동 관리됨.

📌 이 문제에서 의미
문제 문장:

“A security group named FileUsers”

의 의미는:

👉 “권한 관리용 사용자 그룹”

📌 혼동 포인트
Azure에는 이름 비슷한 게 많아:

이름	의미
Security Group	사용자/컴퓨터 그룹
Network Security Group (NSG)	네트워크 방화벽 규칙
👉 완전히 다른 것.

📌 구조
Security Group (FileUsers)
        ↓
RBAC Role 부여
        ↓
Azure File Share 접근
🔑 한 줄 정리
여기서 security group은 네트워크가 아니라, 사용자들을 묶어서 권한을 관리하는 AD/Entra 그룹이다.


You have an Azure subscription that contains a virtual network named VNet1 with Azure Bastion deployed using the Standard SKU. A contractor needs to connect to a virtual machine named VM1 in VNet1 but does not have an Azure portal account. You need to provide secure access for the contractor. What should you configure?

정답은:

Azure Bastion Shareable Link

📌 문제 핵심
상황:

Azure Bastion Standard SKU 사용 중

contractor가 VM1 접속 필요

❌ Azure Portal 계정 없음

✔ 안전하게 접속 제공해야 함

📌 왜 Shareable Link냐?
Azure Bastion Standard SKU에는:

Shareable Link 기능

이 있음.

이 기능은:

Azure Portal 계정 없는 사용자도

특별 링크(URL)로

브라우저 통해 VM 접속 가능하게 해줌

📌 구조
Contractor
   ↓ Shareable Link
Azure Bastion
   ↓
VM1
📌 장점
공인 IP 불필요

RDP/SSH 포트 인터넷 노출 안 함

Portal 계정 없이 접속 가능

브라우저 기반 보안 접속

📌 왜 Standard SKU 중요하냐?
Shareable Link는:

❌ Basic SKU 없음

✔ Standard SKU 기능

문제에서 일부러 “Standard SKU”를 준 이유가 이거야.

🔑 한 줄 정리
Azure Portal 계정이 없는 외부 사용자가 VM에 안전하게 접속하도록 하려면 Azure Bastion Standard SKU의 Shareable Link 기능을 사용한다.
