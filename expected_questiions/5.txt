You have an Azure subscription that contains a storage account named storage1. You assign the Contributor role to User1 at the subscription scope. You also assign the Reader role to User1 at the storage1 scope. What are the effective permissions for User1 on storage1?

In Azure RBAC, permissions are additive, not restrictive.
That means if a user gets permissions from multiple role assignments, Azure combines them.

So in this case:

At the subscription scope, User1 has the Contributor role.
At the storage1 scope, User1 also has the Reader role.

The Contributor role already includes read and write/manage permissions for resources (except assigning roles/access management).

Because Contributor is assigned at a higher scope (subscription), it applies to all resources in the subscription, including storage1.

Therefore, the effective permissions on storage1 are:

Contributor permissions (full management of the storage account except RBAC/access management)

The additional Reader role does not reduce permissions.

A path-based routing rule with a URL path map
Explanation
A path-based routing rule with a URL path map allows you to route requests from specific URL paths to specific backend pools. The URL path map specifies patterns such as /images/* and /videos/* and maps each pattern to a corresponding backend pool. Requests that do not match any URL path pattern are forwarded to the default backend pool. Reference: https://learn.microsoft.com/en-us/azure/application-gateway/url-route-overview
A multi-site listener with hostname filtering
Explanation
A multi-site listener is used for routing based on host names or domain names, not URL paths. Multi-site listeners allow you to host multiple websites on the same Application Gateway IP address, but they route based on the host header, not the URL path. Reference: https://learn.microsoft.com/en-us/azure/application-gateway/multiple-site-overview
A redirect configuration with path rewriting
Explanation
A redirect configuration is used to redirect traffic to a different URL or external site. While path rewriting can modify URL paths, it does not provide the routing functionality needed to direct requests to different backend pools based on URL patterns. Reference: https://learn.microsoft.com/en-us/azure/application-gateway/rewrite-http-headers-url
A basic routing rule with multiple backend pools
Explanation
A basic routing rule forwards all requests on the associated listener to a single backend pool. It does not allow you to route requests based on URL paths. Basic rules cannot be configured with multiple backend pools. Reference: https://learn.microsoft.com/en-us/azure/application-gateway/configuration-request-routing-rules
